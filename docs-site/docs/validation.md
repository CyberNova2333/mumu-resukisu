# 阶段验证、架构决策与迁移约束

本页汇总项目自独立提取以来各阶段实际执行的离线模型检查、主机单元测试与受限环境冷启动验证，同时明确当前版本**未覆盖的范围与硬性迁移边界**。构建清单与局部设备记录保留在本地忽略目录，本页不引入任何本机路径或私有身份凭证。

## 分阶段验证台账

### 阶段一：项目独立提取与离线重建（2026-11-01）

该阶段验证脱离历史试验目录后，在本项目独立结构中重跑工具链与主机模型的基础可靠性（离线清单保留 `deviceValidated: false`，不继承历史试验的通过标志）：

| 验证域 | 实际运行检查与结果 | 明确不代表什么 |
| --- | --- | --- |
| Python 包与离线测试 | 可编辑安装及入口命令可用；初始 75 项主机测试通过（含 29 项 Windows 句柄/故障注入用例与 21 项发行获取用例）。 | 假管理器与临时文件不等于真实 Android 模拟环境。 |
| 原生模块与加载器 | 从固定 Git 提交归档、ACK 源码及原配置在空目录从零编译完成：`kernelsu.ko`（`325384` 字节，SHA256 `39469a8c30b4c2c01475eda91900c195d830a8f9aad68515c423b6157eb9e769`）、`driver-init`（`70920` 字节，SHA256 `306eb1b527f1c03b8fd9d91281f69f235b66f3683850b560c23779ba18cef74b`），精准核对 235 个未定义外部符号、模块结构 `960` 字节及加载器非 PID 1 退出码 `64`。 | 离线符号与 ABI 门禁通过不替代目标实例启动验收。 |
| 内核、分区与 VDI 候选 | `prepare-kernel` 产出与原已验收离线候选摘要相同；`prepare-boot/system/vendor` 经固定槽边界、`e2fsck` 及固定替换校验；`assemble` 重建全部 `2,465,270,784` 虚拟字节并回读一致。 | 原 AVB 树未重签；当时尚未写入模拟器运行。 |
| 用户态与失败模型 | 8 个原生辅助独立编译；6 组 ASAN/UBSAN 场景、32 位调用接口及 11 项直接 32 位模型通过。 | 主机模拟不替代目标系统运行态行为。 |

## 明确未覆盖边界与升级红线

`targets/mumu-android15-x86_64/profile.json` 中的 `refactoredDeviceValidation` 与 `native/driver/target-profile.json` 中的离线验收字段继续保持 **`false`**：

1. **禁止跨系统与跨内核推断**：Android 12、真实物理手机、Enforcing SELinux 策略、未指纹化的 MuMu 引擎版本及第三方通用内核均无支持依据。
2. **禁止推断未验收组件**：`post-fs-data` / `service` / `boot-completed` 三阶段用户脚本生命周期与 32 位守护进程仍缺乏正式重构入口验收。
3. **禁止通过配置放宽升级**：当上游发布新版 APK 或源码标签变化时，必须经过新旧版本差异审计、`register-release.py` 待审材料登记、原生补丁适配与完整冷启动检验，严禁通过改大/放宽既有指纹清单来跳过门禁。

## 关键架构决策记录（ADR）

| 决策项 | 选型方案 | 约束与原因 |
| --- | --- | --- |
| 原厂备份放置域分离 | 将原厂 `dusk` 持久备份与迁移状态置于**数据盘**，而系统盘采用整盘备份事务回退。 | 恢复私有系统盘不会抹除或损坏数据盘上的原厂备份与管理器授权记录，保证多次实验间状态隔离。 |
| 全盘 COW 重组核验 | 每次生成候选后都重读全部 `2,465,270,784` 虚拟字节，而不只验证分区内偏移。 | 防止跨 1 MiB VDI 块边界、父盘引用或零块映射异常悄悄破坏其它逻辑偏移数据。 |
| 发行与目标清单解耦 | `fetch-release`、`register-release.py` 与 `supported-daemons.json` / `target-profile.json` 分离。 | 保证“上游发布新版”不会自动变成“修改了设备早期启动代码或放行未审查的二进制”。 |
| 离线构建独立成档 | 保留历史 `deviceValidated: false` 与各构建清单中的不溯及原则。 | 确保每一个候选包与其实际运行到的设备检查日期、提交版本形成一一对应，不被旧报告污染。 |
