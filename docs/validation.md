构建过程中保留了失败输出：一次Windows挂载路径下的源码解包过慢；一次上游未成功导出用户态头，静默关闭部分功能，导致精确符号集合检查拒绝。最终构建显式执行头导出，并使用新的Linux工作目录从头运行，没有放宽符号门禁。

原实验在独立Android15实例中验证过Root、选定脚本和自建进程附加，作为设计来源保留；本次项目化没有写模拟器磁盘、开启实例或重新验证游戏。Android12、Enforcing、任意模块、任意升级版本及永久安装均不在成功结论内。

重验主机入口：`python -m unittest discover -s tests -v`。原生和用户态构建步骤见 [构建与操作](build-and-use.md)。新候选必须重新完成设备验收后，才能改变其 `deviceValidated` 状态。
