# 一个候选怎样成为可回退安装

假设你持有指纹匹配的原始引擎快照，任务是替换它的Root实现并保留可恢复的原盘。难点是共享基础盘影响其它实例，而运行后的数据也不等于最初候选。本项目先在本地生成差分候选，再把写入限制到明确绑定的私有系统盘，最终得到候选清单、事务记录和精确回退结果。

## Step 1: 确认输入属于已支持的引擎

目标描述记录base摘要、虚拟容量和三个原始分区摘要。提取命令逐一比对；Android版本字符串相同仍不够。原生构建另核对源码提交、配置、编译器和符号集合。不能把未知版本改名当成已支持版本。

获取上游新版是独立的输入准备动作。即使下载到了最新 APK 和固定提交的源码，构建器仍只接受目标描述中已适配的输入；评估新版本需先经过[发行版登记与兼容验证](../modules/release-lifecycle.md)。这一边界防止可变的“最新版”直接改变设备启动代码。

## Step 2: 生成本地替换内容

原生适配补丁处理目标ABI与32位入口；加载器只在早期启动上下文使用。预置工具保留已支持的daemon，缺失时补齐；精确匹配的原厂版本先备份再迁移，其它未知内容则停止。分区编辑取消厂商每次覆盖daemon的旧动作，并把加载器和辅助工具放入固定启动数据槽。原厂文件的识别与可继续运行的支持清单分开维护，不能只改哈希放行未知版本。

这些操作只写新建的本地输出目录。具体输入与产物见 [构建命令](../../docs/build-and-use.md)。内核和镜像原件不随项目分发。

## Step 3: 审计整个虚拟磁盘

组装器按父盘、差分盘、零块和未分配块的真实语义读取VDI，再覆盖允许的分区。例子是一个改动跨过块边界：只有分区内的字节可以变化，边界两侧仍必须与原快照一致。

[镜像测试](../../tests/test_images.py) 包含跨块修改、错误父盘、块别名、边界外改动与错误原始摘要。审计结果保存在候选旁；安装时再次计算，不能单靠JSON里的 `verified:true` 放行。

## Step 4: 绑定实例并安装

使用者提供实例编号和路径，绑定流程实时核对身份、停机和内置Root关闭状态，再记录原私有盘摘要。安装要求三次稳定停机观察，取得独占文件句柄，保存完整备份后才写入。

写入前外部修改不会被“回退”覆盖；写入过程失败则尝试恢复自己的原字节。这一区别见 [镜像与恢复边界](../modules/image-boundaries.md)，由 [事务控制器](../../src/mumu_resukisu/controller.py) 实现。绑定文件与其相邻事务目录应一起保留，不能复制出相互竞争的恢复状态。

## Step 5: 读取证据并恢复

安装成功只代表写盘和读回完成，不代表Android已正常启动。运行验证需另行检查真实Root、脚本和工具行为。首次启动可能在数据盘执行原厂daemon迁移；其备份、失败后重试与磁盘恢复的区别见[迁移与恢复边界](../modules/image-boundaries.md)。结束后使用当前事务号恢复；原始数据盘不会还原，所以迁移备份、管理器、授权和应用数据仍保留。

重构入口已完成固定目标上的安装与回退流程、原厂daemon初装迁移及授权前拒绝验证；授权后再次冷启动仍可取得Root，配套daemon与原厂备份各自的摘要核对通过，固定32位su双入口也已通过。另行以本地受限编排完成单次已有Firefox进程附加、调试开关修改及脱离回收，未扩展为本项目的通用Firefox入口。脚本三阶段生命周期和32位daemon仍未验收，详见[分阶段验证记录](../../docs/validation.md)。历史实验与本轮局部通过均不能扩大为所有模块、Enforcing或Android12支持。运行 `python -m unittest discover -s tests -v` 验证主机逻辑，原生与用户态构建还会执行自身模型测试。
