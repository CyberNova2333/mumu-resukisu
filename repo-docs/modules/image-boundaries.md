# 镜像变化与恢复边界

实例系统盘的“恢复”只针对本次安装前记录的私有差分盘。以一次安装为例：先保存源盘字节及摘要，再写入候选；运行后磁盘内容可能被系统合法修改，但磁盘身份与原备份仍须匹配，才允许恢复。数据盘中的管理器授权和脚本不在这份备份内。

组装时的约束与恢复时不同。组装必须证明允许分区以外的每个虚拟字节保持不变，还要求原有块映射、父盘身份与未允许修改的头部字段保持。恢复依赖已经建立的事务和原备份，不能要求运行过的候选仍与最初构建文件逐字相同。

| 状态 | 动作 | 拒绝条件 |
| --- | --- | --- |
| 写入前检查失败 | 保留当前盘，结束未写入事务 | 外部变化、运行中、基础盘改变。 |
| 写入一部分失败 | 在同一独占句柄中恢复原字节 | 恢复也失败时保留活动事务和错误。 |
| 安装中断，阶段未确定 | 只处理完整匹配原盘或候选的状态 | 未知部分写入不得猜测覆盖。 |
| 已安装后正常回退 | 停止绑定实例，恢复经过核验的原备份 | 实例身份、磁盘身份或备份内容不符。 |

实现位于 [镜像审计](../../src/mumu_resukisu/images.py) 和 [事务控制器](../../src/mumu_resukisu/controller.py)。验证使用 [Windows临时文件故障模型](../../tests/test_controller.py)；模型不代替设备启动验收。

## 启动时的原厂守护进程迁移

首次启动候选时，数据盘可能仍保存原厂守护进程。启动预置先核对新配套文件和待清理的已知观察脚本，只有原厂文件的大小、完整摘要、ELF 身份及文件属性全部匹配，才进入迁移。未知文件、符号链接、硬链接或不符合约束的备份会使启动失败，不能通过改设备上的 JSON 放行。

迁移先在受保护目录保存原厂备份，并同步文件及目录到磁盘，再将原文件移到暂存位置，最后以“不替换已存在目标”的原子操作发布配套daemon。备份从不覆盖；重试也重新核验并同步已有备份。源文件的身份在移动前后复核，目标被其它写入占用时保留占用者和备份。随机临时名让新一次尝试不受旧的未完成临时文件阻塞，旧临时文件不会被当成完成备份。

| 重新检查时的状态 | 预置动作 |
| --- | --- |
| 原厂文件仍在，备份匹配 | 复核并同步备份后继续迁移。 |
| 原文件已暂存，活动路径空缺，备份匹配 | 发布配套daemon，再清理经过复核的原厂暂存副本。 |
| 配套daemon已存在，备份匹配 | 保留活动文件；仅在仍有已知暂存副本时完成清理。 |
| 任一待用文件内容或属性未知 | 保留证据并失败，不覆盖或猜测恢复。 |

原厂备份和迁移状态位于数据盘；系统盘事务恢复不会删除它们，也不会把整个数据盘还原。源文件识别是独立的迁移白名单，不代表原厂版本可作为受支持的 UAPI 版本运行。

实现见[启动迁移](../../native/prestage/stock-migration.h)的 `stock_backup_durable / stock_retire / migrate_stock`，输入依据见[原厂文件记录](../../native/prestage/stock-daemon.json)。[主机模型](../../native/prestage/stock-unit.c)在普通用户的临时文件上注入失败并重试；这验证代码分支，不等于真实断电或设备冷启动验收。

具体使用顺序见 [从输入到回退](../../docs/build-and-use.md)，实现定位见 [代码地图](../code-map.md)。
