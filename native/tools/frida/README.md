# 自有进程的 Frida 验收工具

这里保留已验证方案的监督器、固定测试进程和注入脚本源码。测试进程以 Shell 身份运行，只公开一个固定值函数和本轮随机标识；监督器只运行已固定摘要的官方服务，使用独立的只读安全策略挂载，并移除两项管理能力，避免官方服务修改全局策略。

当前构建目标为 Android 15／x86_64，官方服务为 [Frida 17.19.0](https://github.com/frida/frida/releases/tag/17.19.0)。构建者自行取得并鉴别服务器文件；脚本核对展开后二进制的 SHA256 为 `e6f7e35901db8e83d40088d51692afa77bd23c8ae69e521c3e5955f741a7b9d6`，但不安装或运行它。

```text
python scripts/build-frida.py --ndk-bin <本机NDK的LLVM/bin目录> --server <本地官方server> --port <明确指定的测试端口> --output build/frida
```

在 Windows 上追加 `--wsl-distro`／`--wsl-user` 可选择用于主机模型的普通 Linux 用户。NDK clang 使用宿主版本，GCC 的 ASAN／UBSAN 模型在 Linux 或 WSL 中运行。端口只在忽略的构建目录生成，地址固定限制为回环。两个产物和注入脚本的摘要写入 `manifest.json`。

构建会核对 ELF64、Bionic 动态加载器及目标导出函数，执行14种能力字段、5种挂载别名、输入门禁和管道边界模型。它不会启动模拟器、服务或目标进程，不建立 ADB 转发，也不附加任何进程。

原实验曾完成一次自有目标附加、函数调用、脱离和资源回收。重构项目目前提供可构建源码与主机模型；自动化设备连接、进程身份锁定、端口所有者核验和 host client 调度仍需与新的实例绑定系统集成后另行验收。不能把旧实验记录当成本项目新运行成功。

私有只读挂载是针对固定官方服务实现的约束，不是隔离任意恶意 root 程序的容器。此前成功环境为原本的 Permissive，不代表 Enforcing 或任意应用附加已经验证。监督器仅支持自己的未回收子进程与经过 pidfd 身份检查的自有目标停止，禁止按进程名批量终止。
